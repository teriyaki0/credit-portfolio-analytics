# Где ИИ ошибся и что исправлено

Проект сделан с Claude Code по правилам из [CLAUDE.md](CLAUDE.md). Порядок такой: один шаг — один проверенный коммит,
цифры сверяются с источником и с независимым пересчётом, а ИИ на слово не верим. Ниже — реальные случаи из этой
работы, от самого важного. У каждого указано, как его заметили, — это и есть ответ на вопрос, где ИИ нельзя верить.

## 1. Вывод для риск-комитета получился бы противоположным

**Что было.** По итоговым метрикам ИИ подал снижение NPL на 1,84 п.п. как улучшение: зелёная стрелка на плитке NPL,
а в коммите с метриками цифры «NPL 11,85% → 10,01%» шли без оговорок.

**Как заметили.** Разложили изменение NPL (−10,5 млрд ₸) по кредитам. Всё снижение дали 53 кредита: у них
просрочка за один срез упала с более чем 90 дней (медиана — 217) до 0, реструктуризации нет. Остаток у них уменьшился на 3,9%,
как у обычных платящих кредитов (3,8%), а не как при погашении многомесячной просрочки. Без них NPL вырос бы
на 1,24 п.п.

**Что исправлено.**
- В реестре аномалий появилось правило `dpd_reset_from_npl` с оценкой влияния: NPL 13,09% вместо 10,01%.
- Вывод №1 в README переписан.
- Добавлена матрица миграции по корзинам просрочки, а под KPI на дашборде — сноска о предупреждениях.

**Урок.** Итоговая цифра — ещё не вывод. Нужно знать, из чего складывается её изменение.

## 2. Ловушки «угадывались», а не проверялись

**Что было.** До загрузки данных ИИ перечислил, какая «грязь» почти наверняка есть: разный регистр валют, пустые значения.

**Как заметили.** Профиль данных этого не подтвердил. Реальные проблемы оказались другими:
- 60 полных дублей строк, которые завысили бы портфель на 14,3 млрд ₸ (2,9%);
- 23 кредита, списанные на 01.09 и снова живые на 01.10;
- 434 кредита (20% портфеля) с истёкшим сроком погашения и без соответствующей просрочки.

**Что исправлено.** Каждая гипотеза стала проверкой с числом в `reporting.v_checks`. Неподтвердившиеся тоже
остались проверками со статусом PASS. Найденное ушло в реестр аномалий с вопросами к источнику.

## 3. Ошибка в разрезе, которой не видно на этих данных

**Что было.** В `v_risk_by_segment` разрез определялся через `coalesce(sector, program)`. Кредит с пустой отраслью
молча попал бы в «отрасль» с названием своей программы.

**Как заметили.** На ревью перед коммитом. Цифры на этих данных не менялись, пустых отраслей нет, поэтому
никакая сверка сумм этого бы не поймала.

**Что исправлено.** Разрез определяется через `GROUPING()`.

## 4. Проверки, которые сами не проверены

**Тест дал ложный PASS.** Сломанную YAML-модель подключили через `docker compose run -v`, но монтирование той же папки
из compose её перекрыло. Проверялась настоящая модель, и тест «прошёл». Если бы мы не ждали FAIL, вывод
«проверка работает» был бы неверным. Теперь сломанная копия кладётся рядом с настоящей, и проверка падает
(`npl_amount`, `median`).

**Пояснения противоречили статусу.** Пояснения проверок писали «все в NPL по ставке 50%» даже при FAIL с 93
нарушениями. Это всплыло только на мутационных тестах, когда витрину сломали нарочно. Пояснения переписаны нейтрально.

**Что исправлено в целом.** Появились мутационные тесты (`tests/check_mutations.sql`): 8 типичных ошибок, и каждая
обязана уронить свою проверку. Например, «последний курс вместо курса на дату» завышает портфель на 648 млн ₸ на 01.09,
и это ловит `reconcile_portfolio_kzt`.

## 5. Дашборд «по коду» был готов, а на картинке — нет

**Что было.** Спеки были валидны, ошибок в консоли не было. Но на скриншоте нашлись четыре дефекта:
- служебные номера фасетов над плитками KPI;
- чёрные линии на графиках динамики (у линий `stroke` в стиле Vega-Lite не применяется, нужен `color`);
- страница шире экрана (`vega-embed` делает контейнер `inline-block`);
- обрезанная подпись «4,3%» у самой длинной полосы.

**Как заметили.** Только посмотрев на результат: в браузере и на скриншоте headless Edge.

**Что исправлено.** Все четыре дефекта. В CLAUDE.md добавлено правило: изменения дашборда проверять скриншотом.

## 6. Мелкие технические

- **Экранирование при правке файлов скриптом.** При вставке через скрипт `\r` и `\n` превратились в настоящие
  CR и перевод строки. В первый раз это работало случайно и было замечено при перечитывании. Во второй раз правку
  остановил `assert` в самом скрипте. Теперь файлы с обратными слэшами правятся только редактором.
- **Первый коммит не запустился бы.** Первая версия `docker-compose.yml` ссылалась на файлы следующих шагов.
  По правилу «каждый коммит запускается с нуля» сервисы добавлялись по мере появления.
- **Подпись корзины расходилась с условием.** Корзина просрочки была подписана «90+», хотя условие `> 90`, а кредиты
  ровно с 90 днями лежат в «31–90». Подпись заменена на «>90».
