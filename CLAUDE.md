# CLAUDE.md

Риск-сводка кредитного портфеля: PostgreSQL → семантическая модель в YAML → дашборд на Vega-Lite.
Данные: `data/portfolio.csv` (срезы на 01.09.2026 и 01.10.2026, суммы в валюте кредита),
`data/fx.csv` (курсы к тенге по дням).

## Запуск

```sh
docker compose run --rm loader   # Postgres, sql/*.sql по порядку, проверки, мутационные тесты, выгрузка JSON
docker compose run --rm verify   # то же + независимый пересчёт из CSV на Python и сверка с выгрузкой
docker compose exec db psql -U bi -d credit
```

## Слои

- `raw.*` — CSV как есть. Не чистить, не фильтровать, не пересчитывать.
- `reporting.v_*` — вьюхи поверх raw. Только `CREATE OR REPLACE VIEW`, повторный запуск ничего не ломает.
- Файлы в `sql/` применяются по номеру: `0x` — загрузка, `1x` — витрина, `2x` — метрики,
  `3x` — качество данных, `9x` — проверки.
- `reporting.v_data_quality_issues` — реестр подозрительных кредитов (правило × кредит × дата) с альтернативной
  трактовкой; `v_data_quality_summary` — их влияние на метрики. Новая аномалия = новое правило там же,
  с вопросом к источнику. Витрину правила не меняют.

## Дашборд

- `dashboard/specs/*.json` — спеки Vega-Lite; данные берут из `dashboard/data/*.json`, которые выгружает loader
  после пройденных проверок. Своих расчётов метрик в спеках нет — только форматирование и раскладка.
- Цветов в спеках нет: стили (`kpi-value`, `delta-good`, `dumbbell-link`…) и палитра задаются в `index.html`
  из CSS-токенов, поэтому спеки работают в светлой и тёмной теме. У линий цвет — через `color`, не `stroke`.
- Числа в русской локали (`10,01%`), доли — `.2%`, суммы — млрд ₸.
- `docker compose up -d web` → http://localhost:8080. Скриншот для README: headless Edge/Chrome,
  `--window-size=1280,2200 --virtual-time-budget=20000 --screenshot=docs/dashboard.png`. Изменения
  в дашборде проверять глазами (скриншот), а не только по коду.

## Определения (из задания, менять только явным решением)

- **Портфель** — `principal_outstanding` в тенге по курсу на дату среза, без списанных (`written_off = 1`).
- **PAR30 / PAR90** — доля портфеля с просрочкой строго больше 30 / 90 дней.
- **NPL** — просрочка больше 90 дней **или** реструктуризированный кредит.
- **Провизии** — остаток × ставка: 1% при просрочке до 30 дней, 10% при 31–90, 50% для NPL.
  NPL важнее просрочки: реструктуризированный кредит без просрочки получает 50%.
- **Концентрация** — доля десяти крупнейших групп связанных заёмщиков (`group_id`), не `borrower_id`.

## Правила расчёта

- Курс — строго на `report_date`. Нет курса на дату — это ошибка, а не повод взять соседний или последний день.
- Доли считать как `sum(числитель) / sum(портфель)` на нужном уровне. Никогда не усреднять доли по кредитам.
- Витрина хранит аддитивные суммы в тенге (`portfolio_kzt`, `npl_kzt`, `provision_kzt`); доли — только в метриках.
- Технические исправления допустимы и считаются: полные дубли строк схлопываем.
- Смысловые данные (флаги списания и реструктуризации, просрочку, суммы) в витрине не исправлять.
  Подозрительное считаем по определению, измеряем влияние на метрики и записываем вопрос к источнику.
  Не исключать кредиты молча, чтобы «цифра стала лучше».

## Проверка цифр — где ИИ нельзя верить на слово

- Каждую итоговую цифру сверять: витрина против raw, SQL против независимого пересчёта.
- `reporting.v_checks` — PASS / WARN / FAIL; загрузка падает на FAIL. Сверки в проверках считать от `raw.*`,
  а не через вьюхи витрины, иначе проверка повторит ту же ошибку.
- Отдельно проверять граничные значения (просрочка ровно 30 и 90 дней), курс на дату, дубли, флаги.
- Расхождение не «подгонять», а искать причину.

## Порядок работы

- Один шаг за раз: объяснить, что и зачем → написать код только этого шага → пользователь запускает и смотрит → коммит.
- Следующий шаг — только после коммита предыдущего.
- Коммитить только то, что запускали и проверили. Каждый коммит запускается с нуля.
- Формат коммита: `тип(область): что сделано` по-русски; типы `feat`, `fix`, `test`, `docs`, `chore`.
  В теле — зачем и найденные цифры.
- Ошибку, найденную позже, исправлять отдельным коммитом `fix:`, историю не переписывать.
  Случай записать в `AI_NOTES.md`: что было не так, как заметили, сколько это стоило в цифрах.
- `git push` не делать — публикует пользователь.
